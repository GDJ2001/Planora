# Windows visual smoke test and fix plan

Observed on 2026-10-19 with the installed Planora 0.1.1 release build (`5494dee`) on Windows x86-64. The test used the real authorized helper, a maximized 1536 × 864 desktop window, and a restored window of about 1180 × 790. Overview, Processes, Hardware, Benchmarks, Capabilities, and Settings were visited. Dark and light themes were inspected. This is native visual evidence, not a cross-platform acceptance result.

## Findings

| Priority | Observed behavior | Impact and likely area to investigate |
| --- | --- | --- |
| P0 | Overview summary cards extend past the right edge. At 1536 × 864 the Network card is clipped; at about 1180 × 790 both the fourth card and parts of other content are off-screen. Chart panels also extend rightward, with the second column clipped. | Core telemetry cannot be read. Review available-width calculations and frame padding in `components/cards.rs`, `components/charts.rs`, and the two-column layout in `views/overview.rs`. The measured viewport width must include inner margins and gaps, and child panels must not expand their parent row. |
| P0 | Processes reports 347 rows, yet the main table is nearly blank. A few process names appear to the right of the header, outside the intended row columns. | The primary task-manager view is unusable. Review the distinct header and `ScrollArea::show_rows` body geometry in `components/table.rs`, including column widths, child alignment, clipping, and the actual row height after frame margins and spacing. Confirm with a populated fixture before treating this as a telemetry issue. |
| P0 | Live telemetry changed to **Stale** about 18 seconds after launch and did not recover during the initial pass. The same running app later displayed more than 53,000 seconds of staleness. The Windows helper service was running. | Old values look like current readings. Trace helper IPC request/response IDs, sampler timing, timeouts, reconnection, and UI state transitions. The screen should identify the failed connection or last sample time and clearly mark frozen data. Service status alone does not prove the IPC path is healthy. |
| P1 | The chart drawing area occupies only a narrow strip near the right side of an oversized panel. Blank space dominates CPU and disk charts; the memory and network panels are partially off-screen. | Trends cannot be interpreted. Rework chart sizing after the overview grid is fixed. Reserve bounded widths for axes and legend; give the plot the remaining width and show an explicit empty/stale state when recent samples are absent. |
| P1 | Secondary labels, rates, table values, and settings copy are very small. Source uses 10.5–12.5 point text in several dense regions. The light theme retains the same cramped hierarchy. | Readability suffers, especially at display scaling. Use the brand typography scale: at least 14 logical pixels for primary body data, 12 for secondary labels, and larger key measurements. Test actual 100%, 125%, 150%, and 200% scaling. Capture native screenshots to distinguish font rendering defects from capture artifacts. |
| P1 | GPU and package-power values appear as small unavailable chips while the overview keeps stale CPU, disk, and network values as normal cards. Benchmark actions are disabled without an adjacent explanation. | Availability and freshness are hard to understand. Show reason text and a consistent unavailable/stale treatment in cards, charts, and actions; retain separate capability detail in the Capabilities view. |
| P2 | Hardware canvas clusters four small core tiles at the top-left of a large empty panel. Its accessible-tree alternative is a narrow text block. Benchmarks, Capabilities, and Settings also use only a small part of the viewport. | The information hierarchy feels unfinished. Fit and center the topology graph with package/cache relationships, a useful default zoom, an inspector or legend, and responsive maximum content widths for document-like views. This must follow correctness fixes; do not fill space with decorative data. |

The installed build and helper matched the release artifact, and the helper service was `Running`. The stale condition's cause is **not yet established**. The smoke test did not execute benchmarks or alter process affinity. It did not establish native behavior on Linux or macOS.

## Implementation order

1. **Make telemetry truth visible and recoverable.** Reproduce the stale transition with request/response tracing and helper logs. Add bounded IPC timeouts, reconnect diagnostics, and a clear distinction between live, reconnecting, stale, paused, and unavailable values. Do not retain an old reading without its age beside it. Add a fixture that stops replies after an initial frame and then resumes them.
2. **Repair the layout contract.** Create one viewport-width calculation for overview cards and chart panels, accounting for parent padding, frame margins, and gaps. Use explicit one/two/four-column breakpoints based on *usable* width. At narrower widths, stack panels vertically; do not rely on accidental horizontal clipping or hidden scroll. Test 1024 × 640, 1180 × 790, 1366 × 768, 1536 × 864, and 1920 × 1080.
3. **Rebuild the process table around shared column geometry.** Header and virtualized rows must consume the same computed column widths and origin. If columns exceed the viewport, intentionally expose horizontal scrolling or hide optional columns in a documented order. Ensure the virtualizer's declared row height equals the painted row height, including margins and spacing. Test 0, 1, 347, and 10,000 rows, long names, search, sort, selection, scrolling, and inspector resizing.
4. **Restore chart legibility.** Plot area should use the panel's actual content width; axes, controls, and legends should remain visible. Show loading/no recent data/stale states explicitly. Test 30s, 60s, and 5m histories, dense and sparse samples, missing values, hover, keyboard crosshair, and the table alternative.
5. **Polish hierarchy and states.** Normalize type sizes, padding, control hit targets, status badges, and table density in both themes. Use meaningful responsive layouts for topology, benchmark guidance/results, capabilities, and settings. Preserve Planora resource colors and accessible status labels. Respect reduced motion; use subtle transitions only for fresh data and interaction, never to imply stale data is live.

## Acceptance gates

- No card, chart, table cell, control, or tooltip is clipped or inaccessible at the listed window sizes and Windows scaling values. A layout diagnostic can assert that each primary panel rectangle stays inside the visible content rectangle.
- With a populated fixture, every visible process row aligns with its header and remains selectable. Scrolling does not skip or overlap rows; the selected process identity remains stable across updates.
- A stopped helper or stalled reply changes the state within a bounded interval, labels previously sampled values with age, and recovers automatically when responses resume. Paused display is visually distinct from disconnected telemetry.
- The full chart canvas and both axes are readable; empty, unavailable, and stale series never look like a measured zero. Numeric readouts use clear units and time context.
- Body text and essential graphical elements meet the brand guideline contrast and sizing targets in dark and light themes. Keyboard focus is visible, control names are exposed to accessibility APIs, and reduced motion works.
- Repeat the native visual smoke test on a freshly built installer, then repeat platform-specific layout and scaling checks on Linux and Apple Silicon macOS. Record screenshots, build hash, screen resolution, scaling, and pass/fail per view; do not substitute headless egui tests for native rendering.
